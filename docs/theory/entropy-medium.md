# The entropy medium: information-theory boundary statement

Phase 0 deliverable #3. This document separates six quantities that
popular "infinite storage" claims conflate, then states exactly what
EntropyFS claims and what it never claims.

## 1. The six quantities

| Quantity | Definition | EntropyFS accounting |
|----------|------------|----------------------|
| **Materialized bytes** | `|X|`: the logical byte sequence the application reads/writes | `logical_bytes` |
| **Description length** | `|D|`: the persisted representation descriptor plus all state the decoder needs from disk | `descriptor_bytes + model_bytes + residual_bytes + seed/state + coordinate + references + integrity` (per-extent), plus metadata + GC overhead at FS level |
| **Stored entropy** | `H(D)`: the number of *independent* bits the descriptor selects among. A descriptor with `k` independent bits selects at most `2^k` states | Computed per extent as `log2` of the state-space size actually spanned (exact for rank/unrank; conservatively bounded otherwise) |
| **Logical address space** | The offset range a file may present (`size`) | `logical_bytes` (for the file) |
| **Physical capacity** | Bytes the backing device actually holds | `statfs` basis (ADR-0018) |
| **Effective workload-dependent capacity** | Logical bytes storable for a *specific* workload before ENOSPC | Never a guaranteed number; reported as an observed ratio |

## 2. The counting theorem that governs everything

For a fixed universe `U` (deterministic materialization function with no
hidden inputs), the number of distinct logical byte sequences expressible
with a descriptor of at most `k` independent bits is at most `2^k`. Any
decoder that maps descriptors to outputs is a function

```text
Materialize: D → X
```

so `|{Materialize(d) : d ∈ D}| ≤ |D|`. Information can be *regenerated* only
when the generation function encodes structure — i.e., when the true
generating process of the data has fewer degrees of freedom than its
byte-length. EntropyFS exploits *persisted, versioned, deterministic*
structure; it does not and cannot compress uniform randomness.

## 3. What "stored entropy" means inside EntropyFS

Every representation carries an exact or conservative state-space count:

- `ZERO`/`FILL`/`PERIODIC`: the state is (length, value/pattern, count);
  the span is tiny — that is the point.
- `SPARSE`: exactly `C(n, k)` states for the position subset (checked
  `u128` arithmetic; candidate rejected on overflow) plus `256^k` literal
  combinations. Total span `C(n,k)·256^k`; stored bits
  `ceil(log2(span))`.
- `PALETTE`: multinomial span `n!/(∏c_i!)` (checked; rejected on overflow).
- `PERMUTATION`: factoradic span `m!` for `m ≤ 34` (u128); rejected above.
- `RANS`: the encoded stream length is the stored entropy (the model's
  frequencies are itself stored state, so model bytes are counted).
- `EXACT_REF`: a 32-byte content ID selects an existing chunk; the stored
  entropy is the ID plus the reachability of the target — dedup, not
  generation.
- `BASE_RESIDUAL`: stored entropy = base ID + transform descriptor +
  residual state (positions + literals), all counted.
- `ENTROPY_REF` (`UniformXofV1`): seed (128 bits) + coordinate + residual.
  The XOF output is *generated*; the stored entropy is the descriptor.
  Because the XOF is a uniform random oracle for the purposes of this
  control, `E(seed, coord)` is not structure — so `UniformXofV1` wins only
  when the residual is small, which for random data it is not. That is the
  negative control, by construction.

## 4. Integrity as stored entropy

Hashes/CRCs are themselves persisted state (32 bytes BLAKE3 per chunk
logical ID, 4 bytes CRC32C per record). They are counted in
`integrity_bytes`. Deduplication systems that forget to count their indexes
overstate savings; EntropyFS counts the content index as a derived,
*recoverable* structure (rebuildable from segments) but still reports its
marginal cost in `status`.

## 5. The honest claim

> For data generated by a process with fewer effective degrees of freedom
> than its byte representation — repetition, low cardinality, sparsity,
> permutation structure, periodicity, versioned similarity, cross-file
> sharing — EntropyFS persists the irreducible state and materializes the
> structure, so that `stored_entropy + integrity + metadata < logical_bytes`,
> with every bit accounted.

The dishonest claim, which EntropyFS rejects:

> "A 128-bit seed stores a gigabyte of information."

A seed materializing a gigabyte is a *generator*, and the gigabyte of
generated output is not independently stored information. EntropyFS says
this out loud in `explain`, `inspect`, and every benchmark
(`docs/theory/information-accounting.md`).

## 6. Workload-dependence

`effective_capacity(workload) = physical_capacity / mean_stored_ratio(workload)`
is an observation, never a guarantee. `statfs` reports physical capacity;
the ratio is reported separately (ADR-0018).
